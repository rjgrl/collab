## Forms defect and focused correction

The prior handler upserted alumni and then wrote an import job without a single transaction or durable replay record. Source review established these missing controls; this phase did not claim a newly demonstrated pre-fix production exploit. Fault-injected real-DB acceptance now demonstrates rollback after alumni/tracking writes and before job creation. No partial alumni, tracking, receipt or job remains, and the same key succeeds on a healthy retry.

`FormsReceipt.keyHash` is unique and its payloadHash binds a stable sender ID to validated business fields. Receipt, alumni/tracking mutation and completed job commit in one transaction. Duplicate accepted IDs return the original job without another mutation. Conflicts are retried at most three times; unresolved contention returns 503/Retry-After. The observed eight-request run included one temporary 503; a retry settled successfully. Six distinct accepted IDs produced six jobs/receipts, four unique alumni and four tracking records. Archived alumni are rejected. [Sender/operations contract](../operations/FORMS_WEBHOOK.md).

## Additional confirmed packaging issue

Expanding the rehearsal to complete build artifacts exceeded its 64 MiB bound because `copy-prisma-engine.mjs` copied four failed-generation temporary DLLs along with the finalized engine. Approximately 84.7 MB of temporary bytes were included. The build now copies only finalized engine filenames ending `.node`; the regression checks that a directory containing only a temporary file fails and that adding a real engine copies only that engine. No manual deletion of the unrelated generated source files was performed. The normal build cleaned/recreated its own output.
