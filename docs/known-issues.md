# Known issues and gotchas

- After an email-provider update, a form that still reports "HTTPS gateway URL is required" is talking to an old API process. Vite updates the frontend independently, but a non-watching `tsx --env-file=.env src/index.ts` server retains the previous credential schema. Stop the stale API and restart `pnpm dev` (or `pnpm dev:server` if the frontend is already running); do not add a fake gateway URL. Current Gmail settings require a real Gmail address and Google App Password, not a Resend/SMTP2GO key. The setup test goes to that Gmail inbox, not the seeded `collab.test` account.

Format: symptom, cause, workaround. Remove an entry when it is fixed.

- `docs/` is an allowlist in `.gitignore`. A new doc stays untracked until it gets a `!/docs/<file>` entry.
- Only `.claude/agents/` and `.claude/skills/` are tracked. New shared Claude config elsewhere under `.claude/` needs its own `!` entry in `.gitignore`.
- The GateGuard hook blocks the first Bash call of each session until the request and the command's purpose are stated. Workers will hit it too: state both, then retry.
- Local MongoDB runs on port 27018 as a replica set, not on 27017. Transactions need the replica set.
- Every browser test fails with `browserType.launch: Executable doesn't exist` on a fresh machine. Cause: Playwright's Chromium is not installed. Workaround: `pnpm exec playwright install chromium` once per machine.
- Browser tests and `*-local.ts` checks fail with `ECONNREFUSED 127.0.0.1:27018` after a reboot. Cause: the local replica set is not running. Workaround: `pnpm db:local` (it starts a detached `mongod`).
- `pnpm exec vp fmt <directory>` can hang on Windows. Workaround: pass individual files.
- Scripts that write files in text mode on Windows (for example Python's `open(p, "w")`) produce CRLF and `pnpm check` reports formatting errors. Workaround: write with LF (`newline=""` in Python); `.gitattributes` normalizes on commit, but the check runs on the working tree.
- Setting provider env variables in production does not configure integrations: production strips those values and reads encrypted `IntegrationSetting` credentials instead. Use the Super Admin Settings › Integrations UI with the correct `INTEGRATION_ENCRYPTION_KEY`; do not reseed populated Atlas to import keys. Sheets has no separately consumed JSON env variable: choose its **own** account in the UI for identity separation. See [API setup](operations/API_SETUP.md).
- New server environment keys. `INTEGRATION_ENCRYPTION_KEY` (64 hex) is required in production and must differ from `MFA_ENCRYPTION_KEY`, `SESSION_SECRET` and `BACKUP_ENCRYPTION_KEY`; `pnpm setup:local` generates it for new checkouts, but existing local `apps/server/.env` files need it added by hand to save integration credentials. Backups need `BACKUP_ENCRYPTION_KEY` (64 hex, distinct), an absolute `BACKUP_DIR` outside `UPLOAD_DIR`, and `MONGODB_TOOLS_DIR`; without them Settings › Backups shows what is missing and backups return 503.
- `mongodump` and `mongorestore` are not part of the MongoDB Server install. Run `pnpm tools:mongodb` for the pinned, checksum-verified Windows/Ubuntu x64 package (see `docs/operations/DISASTER_RECOVERY.md`). Note: `mongodump` has no `--nsExclude`; use `--excludeCollection`.
- Local website edits do not appear in Atlas after a one-time import. Cause: the development backend still uses native MongoDB, while Atlas holds an independent snapshot; there is no automatic synchronization. Compare current records and approve a targeted refresh, or complete the separate hosted-backend cutover. Do not point local development/tests at Atlas or blindly overwrite the Atlas database to reconcile profile changes.
- Atlas `mongodb+srv` SRV/TXT resolution can fail with `ECONNREFUSED` from the system DNS resolver even when the cluster is reachable. Diagnose DNS separately from authentication. A process-local resolver can verify connectivity without changing OS DNS; native tools can use privately configured seed hosts derived from the Atlas SRV/TXT records, with verified TLS and the correct replica set/auth source. Never disable certificate checks or broaden Atlas Network Access to `0.0.0.0/0` as a workaround.
- Atlas connection examples contain credential placeholders. Privately check for unchanged placeholders before attempting authentication; replace the whole placeholder, including its angle brackets, unless those characters really belong to the password. Use the Atlas database user's credentials, not an Atlas/Google account password, and URL-encode special characters. Never print the URI or put it in command arguments.
- In-app maintenance mode exempts Super Admins and sign-in endpoints, so it is not a complete write freeze. For a native database copy, either stop all writers or verify consistent source-snapshot hashes before/after the dump and exact restored hashes. Restore the previous maintenance state on both success and failure; exclude machine-specific `BackupState` from the dump/restore.
- Integration credentials are cached per server process for 5 seconds. Test fixtures that mutate their `IntegrationEnv` object at runtime must call `invalidateIntegrationEnvCache()` afterwards, or the next request sees the old values (this caused an SMS verification flake).
- `pnpm test:roles-local` needs `.tools/test-accounts/latest.txt` from `pnpm accounts:local` first.
- Stopping a Playwright run through a background job on Windows can leave its fixture and Vite processes alive on ports 3100/3101; the next run then fails with "already used". Kill the orphaned node processes (not your own `pnpm dev`).
- Editing or deleting files under `apps/web/src/routes` while a Vite dev server or Playwright run is active regenerates `routeTree.gen.ts` without them; `pnpm check` then fails with route type errors. Start Vite once (`pnpm --filter web exec vp dev`) to regenerate.
- CI starts its own MongoDB through `mongodb-memory-server` (`apps/server/test/local/ci-replica-set.ts`) whenever `CI=true`. The version must be a published download: 9.0.0, 9.0.1 and 9.0.3 do not exist, 9.0.2 does. Running a `*-local.ts` script with `CI=true` while `pnpm db:local` is running fails because both want port 27018.
- Integration connection-test mocks must use each provider's real response format (for example reCAPTCHA's `error-codes` with a hyphen). A made-up field once let any reCAPTCHA secret pass.
- Adding a JSON endpoint: add it to `packages/contracts/src/api-routes.ts` (the web client picks it up), mount it under `/api` in Express (`/api/v1` is rewritten there), then run `pnpm openapi`. `pnpm test` fails if the route is missing on the server or the spec is stale. Multipart, download and redirect endpoints go in `RAW_ROUTES`.
- A harness response named `rate_limit_error` can be the external model provider's account quota rather than this application's authentication throttle. Confirm the failing request and provider before changing app middleware. For large local Playwright selections, any raised `AUTH_IP_LIMIT` / `AUTH_ACCOUNT_LIMIT` must be command-scoped; run the final suite with defaults to prove the application limiter remains enabled.
- `tests/browser/ui-modernization.spec.ts` "workspace remains accessible…" can fail on desktop at the synthetic dashboard outage step ("Could not load dashboard" alert not visible within 15 s) on slower machines. It fails identically on untouched `d83726d`, so it is not caused by later changes; the mobile project passes. Likely the client's retry/backoff exceeding the 15 s wait; investigate before relying on that step.
- On Windows, running a formatter while another check maps the same files can fail with `os error 1224` (“user-mapped section open”). Finish formatting before starting `pnpm check`; do not run those commands concurrently on the same paths.
- Capitalization-only UI changes also affect raw CSS selectors such as `[aria-label="Authenticator Setup Key"]` and tests that derive label text from API catalog names. Update those alongside `getByRole` selectors; smoke-test shared MFA enrollment before running broad browser suites. Do not recase stored data or weaken authorization assertions to match presentation changes.
- Anything absolutely positioned inside a scrolling table (for example `sr-only` button labels) escapes the scroll clipping unless the scroller is `relative`. On emulated phones this silently widens the whole page (390px became 597px) and pushes dialog buttons off-screen; `scrollWidth <= innerWidth` cannot catch it because `innerWidth` grows too. Compare `innerWidth` with `page.viewportSize().width` instead.
- After 2026-11-15, `main` was force-pushed once to drop an empty duplicate commit (files unchanged). An older clone shows `main` as diverged. Workaround: `git fetch origin` then `git reset --hard origin/main` on that clone (after saving any local work).
- Schema version 3: the server exits at start with "Timestamp-ordering collections or indexes are missing" until `pnpm db:migrate --apply` has run. It is additive (three metadata collections). Stop every API instance sharing the database before migrating; an older running version bypasses the ordering checks.
- Protected alumni writes (`PATCH /alumni/:id`, employment create/update/delete, `POST /alumni/assign`, and account-name changes for linked accounts) now return 409 `TIMESTAMP_CONFLICT` without an `X-Timestamp-Edit` header from `POST /alumni/timestamp-edits`. Local scripts and tests must obtain a context (see `apps/server/test/local/timestamp-helper.ts`); do not add a bypass. Two edits open on the same alumnus: the older one is rejected when it saves, by design.
- Schema version 2: the server exits at start with "Legacy roles (viewer, admin or staff) are still in the database" until `pnpm db:migrate --apply` has run. Back up first; the rename and role removal are not reverted by `--rollback`.

- `git fetch origin` did not update `main` or PR branches on this clone because `remote.origin.fetch` only listed `development/phase6-cross-device-testing`. Fixed on this machine with `git config --replace-all remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"`; check other clones the same way.
- `main` is protected. Merge with a PR after all eight checks pass; `git push origin main` and force-pushes are refused (GH006).

## Security follow-ups (open)

- SMS delivery is deliberately unconnected (`packages/api/src/integrations/sms.ts`). With phone verification required, production `/health/ready` stays 503 and new alumni cannot finish verification until an SMS provider is wired or the phone requirement is changed.
- Email gateway: DNS can still change between the per-send public-address check and the connection (DNS rebinding). Only a Super Admin can set the gateway. Fix: allowlist the provider host (for example `api.resend.com`) or pin the resolved address with undici.
- Password-reset requests may reveal which accounts exist through response time (the eligible path writes a record and calls the gateway). Not measured locally; fix by sending in the background or padding to a fixed time. Sign-up also says "An account with that email already exists."
- No TTL cleanup for expired `Session`, `AuthThrottle`, `PasswordReset` and `VerificationChallenge` records; they are rejected in code but accumulate.
- Product decision pending: `/me/profile` returns the alumnus's assigned faculty name.
